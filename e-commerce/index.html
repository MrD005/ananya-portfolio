01

Overview

The exploration

Go beyond static screens and design how choices change the experience.

The project explored how conditional prototyping could make a familiar commerce flow feel more responsive and understandable.

I designed a compact journey from browsing products to reviewing details and managing a cart.

The emphasis was on state: selections, quantity, cart contents and coupon feedback needed to respond visibly to user actions.

Design question

How might a prototype communicate the consequences of each shopping decision?

02

Challenge

Where friction appears

Checkout becomes confusing when the interface stops reflecting user intent.

The concept focused on common breakdowns across the purchase journey: unclear selection state, weak feedback and a cart that does not make totals easy to understand.

01

Choices need feedback

Variant and quantity selections should visibly update before the user commits.

02

Actions need continuity

Moving from product details to the cart should preserve the choices already made.

03

Totals need transparency

Subtotal, delivery and discounts should be understandable before checkout begins.

04

Errors need a response

Coupon and cart states need immediate, specific feedback instead of silent failure.

03

Approach

Design process

Prototype the decision logic, then refine the visual layer.

  1. 01

    Identify friction

    Review common shopping patterns and frame the points where a user needs clearer guidance.

  2. 02

    Map the core journey

    Connect discovery, product details and cart review into a short end-to-end path.

  3. 03

    Build conditional states

    Use Figma variables and branching interactions to make the prototype respond to selections and cart changes.

  4. 04

    Test and iterate

    Review whether each state is understandable, then refine labels, hierarchy and feedback.

04

Prototype

Three connected moments

Each screen answers the next question in the purchase journey.

05

Learning

What I took forward

A convincing prototype explains behavior—not only appearance.

Conditional prototyping made it possible to test how product and cart states respond to user choices before implementation.

The exercise strengthened my approach to interaction logic, feedback and edge cases while keeping the primary journey easy to follow.
